## 1. OAuth Provisioning & Network Connectivity
- Connected Grok Bot via official Tailscale plugin OAuth flow (Google login consent).
- Provisioned device on tailnet: `grokbot-user-35173201` (Linux 6.12.113, `1.104.6`, user-owned by authorizing account, Connected).

  - Observed UI error during state transition / ownership mismatch: `The Grok Bot device is no longer owned by the Tailscale login it signed in as, so Grok Bot signed it out.` — indicates Grok Bot enforces user-ownership on its OAuth-provisioned device (converting the device to tag-owned risks breaking the connector).

## 2. Grok Bot Egress Proxy Architecture & HTTP vs HTTPS Finding
- Grok Bot's cloud box does NOT run a local `tailscale` daemon; it routes traffic through an outbound proxy (`SAND_HTTP_PROXY_NAME`, `SAND_EGRESS_TUNNEL_PROXY_ADDR`, Server: Pingora) out via `grokbot-user-35173201`.
- Reachability constraints observed from Grok Bot box:
  - Full MagicDNS FQDN (`<host>.<tailnet>.ts.net`) works over TCP/HTTPS.
  - Short hostnames, raw `100.x` IPs, and ICMP ping do NOT route through the proxy.
  - Plain HTTP (`http://...`) via curl returned proxy HTTP 500 before plugin/HTTPS activation; enabling Tailscale Serve HTTPS (`tailscale serve --bg --https=443 18352`, Funnel OFF) resolved TLS cleanly.
